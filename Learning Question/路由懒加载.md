你现在在学 React 路由（前面问过 `Navigate`、`HashRouter`），那我用 **React 项目场景** 给你讲清楚什么是“路由懒加载”。

------

# 一、什么是路由懒加载？

## 🔹 正常写法（没有懒加载）

比如：

```tsx
import Discover from '@/views/discover'
import Mine from '@/views/mine'
import Download from '@/views/download'
```

问题是：

👉 **项目一启动，这些页面代码就全部打包进主文件里**
👉 不管用户进不进这个页面，都会一起下载

就像：

> 你只想去一楼，却把整栋楼的东西都搬出来了。

------

## 🔹 懒加载是什么？

懒加载就是：

> **用到的时候再加载**

只有当用户访问 `/mine` 时，才加载 Mine 组件的代码。

------

# 二、React 里怎么实现懒加载？

用的是：

- `React.lazy`
- `Suspense`

示例：

```tsx
import React, { lazy, Suspense } from 'react'

const Discover = lazy(() => import('@/views/discover'))
const Mine = lazy(() => import('@/views/mine'))

function App() {
  return (
    <Suspense fallback={<div>加载中...</div>}>
      {/* 路由配置 */}
    </Suspense>
  )
}
```

------

# 三、它底层做了什么？

原来打包是：

```
main.js （包含所有页面代码）
```

使用懒加载后变成：

```
main.js
discover.chunk.js
mine.chunk.js
download.chunk.js
```

👉 访问哪个页面，就加载哪个 chunk 文件

这叫：

> **代码分割（Code Splitting）**

------

# 四、为什么要懒加载？

核心就一句话：

> 🚀 提高首屏加载速度

详细一点讲：

### 1️⃣ 减少首屏体积

如果你的项目有：

- 首页
- 个人中心
- 下载页
- 设置页
- 订单页
- 10个大组件

全部打包可能 3MB。

用户只进首页，却下载 3MB，很浪费。

------

### 2️⃣ 提升用户体验

首屏更快打开。

尤其：

- 移动端
- 网络慢
- 服务器在国外

懒加载效果特别明显。

------

### 3️⃣ 更适合大型项目

小项目（3个页面）无所谓。

大型后台管理系统 30+ 页面：

不用懒加载，首屏直接爆炸。

------

# 五、通俗类比

想象一个商场：

❌ 不懒加载 = 一进门，所有商铺的灯全部打开

✅ 懒加载 = 你走到哪一层，哪一层才开灯

------

# 六、什么时候不用懒加载？

1. 页面特别少
2. 首屏页面本身就很大（首页不建议懒加载）
3. SEO 要求极高（需要 SSR）

------

# 七、你现在项目里适不适合？

你之前写的是这种：

```tsx
import Discover from '@/views/discover'
```

如果只是练习项目：

👉 可加可不加

如果你想往真实项目靠拢：

👉 建议学会懒加载写法

------

# 八、一句话总结

路由懒加载就是：

> 只有访问该路由时，才加载对应页面代码。

目的是：

> 减少首屏体积，提高加载速度。
