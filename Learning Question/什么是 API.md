什么是API

API，其实你可以把它理解成——**软件和软件之间的“对话规则”**。

我们拆开说：

API = Application Programming Interface
 中文叫：**应用程序编程接口**

但这个名字很吓人，其实很好懂 👇

------

## 🍔 用点外卖来理解 API

想象一下你在餐厅吃饭：

- 你 = 前端
- 厨房 = 后端服务器
- 菜单 = API

你不会自己跑去厨房炒菜，对吧？
 你是通过“菜单”告诉服务员你要什么。

👉 菜单规定了：

- 你可以点什么（接口地址）
- 要怎么点（请求方式 GET / POST）
- 要给什么信息（参数）
- 最后会给你什么（返回数据）

这张“菜单”就是 API。

------

## 🧠 用程序角度理解

比如你在写 React 项目：

```
fetch("https://api.example.com/user/1")
```

你在干嘛？

- 向某个地址发请求
- 按 API 规定传参数
- 等它返回数据

这里的 `https://api.example.com/user/1` 就是一个 API。

------

## 🏗 API 的本质

API 就是：

> 一个程序向另一个程序“要数据”或“让它做事”的规则说明书

------

## 💡 API 不只是后端

API 不一定是网络请求，它也可以是：

### 1️⃣ 浏览器 API

比如：

```
localStorage.setItem()
```

这是浏览器给你的 API。

------

### 2️⃣ React API

比如：

```
useState()
useEffect()
```

这是 Meta 开发的 React 提供的 API。

------

### 3️⃣ 操作系统 API

比如 Windows 提供文件读写 API。

------

## 🔥 超简单总结

API 就是：

> 软件之间交流的规则

它解决的是：

- 我能用你什么功能？
- 我要怎么用？
- 你会返回什么？

------

## 🚀 再浓缩一句

API 就是：

👉 **我不需要知道你怎么实现，我只要按规则调用你就行。**
